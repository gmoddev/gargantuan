title: Porting from Roblox
description: Familiar APIs with Engine-defined behavior and explicit compatibility limits.
---

Gargantuan is an independent runtime. A Roblox game is not expected to run
unchanged. Check each class, service, asset and authority assumption against
the [API reference](../../api/) and current source declarations.

## Implemented conventions

- Obtain Workspace with `game:GetService("Workspace")`; do not assume a
  `workspace` global.
- Runtime scripts use `Script` and its execution context. Do not assume
  `LocalScript`, `BaseScript` or `Humanoid` supplies Roblox behavior.
  The current actor model is `Character` with Engine-shipped player policy
  and explicit native motion authority.
- Signals and connections have Engine-specific bindings and teardown behavior.
  See [Instance APIs](../../api/instances-and-services/).
- Import assets through the Engine pipeline. Roblox `rbxassetid://`
  identifiers are not canonical Engine identities. See
  [assets and rendering](../../api/world-and-rendering/).
- Studio plugins use the Studio-owned bounded boundary; gameplay Luau receives
  no ambient editor-authoring capability.

## Old compatibility examples

`src/Main.cpp` parses `--enable_roblox_compat`, but parsing a flag does not prove
a general compatibility layer. The previously documented `--compat-roblox`
flag, `project.config.json` compatibility toggle and promise of complete API
parity are not supported contracts.

Use [runtime schema](../../developing/runtime-schema/) for the frozen PreRun
custom-class/extension model. The old `InstanceClass.new` registration sketch
is not an implemented gameplay API. Use [native networking](../../developing/current-networking/)
and actual [persistence boundaries](../../api/networking-and-persistence/)
instead of assuming Roblox platform services exist.

The [first complete game](../../../../../samples/FirstCompleteGame/README.md)
shows integrated Scripts, canonical assets, Character control, GUI and packaging.
