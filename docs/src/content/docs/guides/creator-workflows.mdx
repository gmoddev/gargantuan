The standalone lifecycle campaign owns application menus, gameplay pause, hosting, joining and returning to the menu. Those changes are outside this documented source. Main-menu registration and session signatures require its qualified recipient and a separate metadata refresh. Existing direct-start projects use the selected runtime's normal package lifecycle. A menu's visibility alone does not suspend a multiplayer Server's authoritative simulation.

PreRun registration belongs to project schema setup. Runtime Scripts execute with their own client/server context and capabilities. A type declaration cannot grant a permission. Native metadata can leave defaults or yielding behavior unspecified. Treat such missing fields as a documentation backlog and follow the linked subsystem contracts before relying on them.
