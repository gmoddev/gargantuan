title: Block construction and independent spaces
description: Place, edit, pick and save native blocks in Workspace and in independent domains.

Create a `BlockGrid` from an authoritative gameplay Script. The default block is visible and collidable as soon as you place it.

```luau
local Wall = Instance.new("BlockGrid")
Wall.Name = "GardenWall"
Wall.Parent = workspace
Wall:SetBlock(Vector3.new(0, 0, 0), "Stone")
Wall:Fill(Vector3.new(0, 1, 0), Vector3.new(12, 3, 1), "Brick")
```

This wall has 25 blocks and one grid Instance. `Fill` includes the minimum coordinate and ends immediately before the maximum. The brick courses therefore occupy X coordinates 0 through 11 and Y coordinates 1 and 2. A grid may span the whole world. Create another when a construction needs its own transform, identity, visibility or collision settings.

## Pick and remove one cell

```luau
local Hit = Wall:Raycast(Vector3.new(5.5, 8, 0.5), Vector3.new(0, -12, 0))
if Hit then
	print(Hit.Cell, Hit.Block.Definition)
	Wall:RemoveBlock(Hit.Cell)
end
```

The direction vector includes the length of the ray segment. A grid raycast returns the individual block even where one collision shape serves several cells. To compare the grid against ordinary Parts in a world query, set `Params.IncludeBlockGrids = true` on a new `RaycastParams`, then call `workspace:Raycast`. An ordinary Part hit has no `GridHit`. Terrain participates when you also enable `IncludeTerrain`.

## Work in local coordinates

`GetBlock(Cell)` returns the definition and orientation, or `nil` for verified air. On a network client check `IsRegionAvailable(Cell, Cell + Vector3.new(1, 1, 1))` first. A read outside the installed window raises an availability error. `CellToWorld` returns a cell center and `WorldToCell` locates the containing cell. For an empty grid, set `CellSize` to 0.5, 1 or 2 before building. Moving `CFrame` moves existing cells together. The same local coordinate continues to identify the same block.

Use `Clear(Min, MaxExclusive)` to remove a box. `ReadRegion` returns occupied cells and the revision of the read. Point and box edits are atomic. Keep opaque revision strings with their issuing grid and current world. In this implementation a single fill or clear visits up to 32,768 cells and a region read covers up to 4,096 cells. A large build can use several bounded edits. Each edit may also reach a physics or storage budget, so arrange large batches around meaningful application changes.

## Define an oriented block

Register a shared shape once per grid. A definition key begins with `project:` and uses lowercase letters. Local ports rotate with the block. Choose perpendicular directions for `Up` and `Front`.

```luau
Wall:DefineBlock("project:ledge", {
	Shape = "Slab",
	Color = Color3.fromRGB(174, 131, 89),
	Ports = {"+X", "-X"},
})
Wall:SetBlock(Vector3.new(0, 3, 0), "project:ledge", {Up = "+Y", Front = "-Z"})
```

The primitive shapes are `Cube`, `Slab`, `Wedge` and `Stairs`. Set `Collision = "None"` for a decorative piece. Set `Queryable = false` to exclude it from picking. Replacing a definition updates its existing cells. Pass the grid's current revision to `ReplaceDefinition` and use `GetDefinitionDigest(Key)` to compare the content of a particular definition.

## Commit one gameplay change

A server can place a cell and set gameplay state in the same edit. Declare each channel once. Its default is shared, so a cell only needs storage for a value that differs from the default.

```luau
Wall:DefineChannel("powered", {Kind = "Bool", Default = false, Indexed = true})
local Cell = Vector3.new(0, 3, 0)
local Edit = Wall:BeginEdit()
Edit:SetBlock(Cell, "project:ledge")
Edit:SetValue(Cell, "powered", true)
Edit:Commit()
assert(Wall:GetValue(Cell, "powered"))
```

Use `BeginEdit(ExpectedRevision)` after a read that drives a decision. If another writer changes the grid before commit, the stale edit fails as a unit. Read the affected cells again before deciding whether to retry. Call `Cancel()` to discard pending commands. An edit accepts up to 1,024 commands and is also bounded by visited cells and provider capacity.

Channels support `Bool`, `UInt8`, `Int32` and `Float32`. Choose `Persistent = true` for authored save data, `OnCopy = "Value"` for values that should follow copies, and `Indexed = true` when gameplay needs to enumerate nondefault entries. The default network audience is server-only. `Audience = "RelevantPeers"` opts a channel into the public projection for an admitted peer.

## Process a connected component in batches

```luau
local Search = Wall:FindConnected({Cell}, {
	Bounds = {Min = Vector3.new(-8, 0, -8), MaxExclusive = Vector3.new(8, 8, 8)},
	Adjacency = "Face", UsePorts = true, MaxVisited = 128,
})
while true do
	local Page = Search:Step(32)
	for _, Position in Page.Cells do
		print(Position)
	end
	if Page.Status ~= "More" then break end
end
```

With `UsePorts`, each face connection requires a matching port on both oriented neighbors. `StopAt` can finish the traversal when it finds a particular definition. A traversal pins the grid state it started from. Compare its revision with the live grid before applying decisions. `FindActive(Channel, Bounds)` uses the same paging interface for an indexed channel. A limited, expired or canceled traversal can return a partial result. Only a completed traversal establishes that the component was exhausted.

For rectangular selections, `ReadRegion` accepts a definition list or a channel equality filter. `ReadPacked` returns a palette, its definition digests and an X-fastest buffer. Use an edit's `WritePacked` to validate and apply it. For copying within a grid, `CopyRegion` and `MoveRegion` work on native cells inside the same edit.

## Model durability and repair

The optional `samples/BlockGridGameplay/Masonry.luau` ModuleScript stores wear on damaged blocks. Place it next to `MasonryExample.server.luau` and name the ModuleScript `Masonry`. The example builds a hollow workshop and cuts its doorway in one transaction. One `GetPropertyChangedSignal("BlockRevision")` notification covers the entire edit. For a hit on an occupied cell, the server adds wear or removes the block when it reaches 100. The example repairs a weathered 99-cell roof by scanning indexed overrides in batches of 32 operations.

```luau
local Masonry = require("./Masonry")
Masonry.DefineWear(Grid) -- once for a new construction
Masonry.Damage(Grid, Hit.GridHit.Cell, 25)
local Repaired, Status = Masonry.Repair(Grid, Min, MaxExclusive)
```

Repair yields between cursor pages. It returns the number of cells already repaired and a status. If another edit changes the revision during a yield, it returns `Changed` and the game can schedule a fresh pass. Undamaged cells share a zero default. The game chooses which constructions receive this channel and when repairs run.

## Give an interior its own space

```luau
local Room = Instance.new("SpatialRegion")
Room.Name = "Workshop"
Room.Parent = workspace

local Floor = Instance.new("BlockGrid")
Floor.Parent = Room
Floor:Fill(Vector3.new(-8, 0, -8), Vector3.new(8, 1, 8), "Stone")
workspace.CurrentSpatialRegion = Room
```

The floor can use the same coordinates as an outdoor wall. Query `Room` for interior geometry. Query `workspace` for outdoor geometry. Set `workspace.CurrentSpatialRegion = nil` to view the outdoors again. View selection changes what the camera renders. A character's physics affiliation is a separate decision. For a Part or BlockGrid that belongs elsewhere in the Instance hierarchy, set its `SpatialRegion` explicitly. Both the object and destination must belong to the same live DataModel.

Each region exposes its own `Terrain` alongside its Parts and block grids. Smooth terrain and discrete construction can use different resolutions. Project save and reopen bind each authored terrain field to its own spatial owner. A packaged offline scene carries the field artifacts it needs.

## Author and save in Studio

Insert a BlockGrid under Workspace or a SpatialRegion. Select it to open its cell inspector. Enter an integer cell and a size to fill a box with Stone or Brick. Use the adjacent-cell control to build against a picked face. Removal, Undo and Redo operate on the native field. Save the project to keep edit-world changes. Play starts with independent native resources. Stop returns to the authored construction.

To reuse a group of cells, select its source grid and enter the two corners in the grid inspector. Copy the selection, select the destination grid, choose an anchor cell and inspect the rotated preview before pasting. Air inside the selection can clear an occupied destination cell. Undo and Redo operate on the complete paste. An edit to either grid after preview can invalidate the operation. Refresh the preview against the current revisions before pasting.

For a custom mesh, import it into the project's asset catalog. Use the inspector's asset picker to choose the visual mesh, its companion collision when needed, and a material. Give the definition a project key, place a cell and save. On reopen, the grid resolves those project assets again.

To give a grid or Part its own domain assignment, select it in Explorer and search Properties for **SpatialRegion**. Choose the domain by its Explorer path and apply the change. **Use parent domain** clears that explicit assignment. A grid can stay under Workspace in Explorer while its cells belong to the workshop's coordinate space.

Select **Workspace** or a **SpatialRegion** in Explorer to inspect its Parts, grids, terrain collision and active collision requests. **Show in viewport** switches the edit camera to that coordinate space. To hold local collision during startup, enter minimum and maximum coordinates and a duration, then choose **Add collision preload Script** and save. The generated server Script calls the public `RequestCollisionArea` method. During Play, **Inspect Play view** shows the live camera's domain and how many requests are ready. Stop restores the Edit world and its own counters.

## Enter a room through a door

In a running server Script, choose the room and a clear landing position after checking the player's permission and distance to the door. Pass the authenticated Player received from your interaction handler. The corners below are in the room's coordinates and enclose the arriving character.

```luau
local function EnterWorkshop(Player, Room)
	local Landing = Vector3.new(0, 5, 0)
	local HalfSize = Vector3.new(4, 4, 4)
	local Request, Reason = Player:RequestSpatialTransfer(
		Room, CFrame.new(Landing), Landing - HalfSize, Landing + HalfSize)
	if not Request then return false, Reason end
	local Status = Request:GetStatus()
	while Status == "Pending" do
		task.wait(0.05)
		Status = Request:GetStatus()
	end
	return Status == "Applied", Status
end
```

Use `workspace` as the destination for a return door. On `Applied`, tell the originating player's view to display its new room. A viewport selection by itself only changes the camera's world. On `CommittedUnconfirmed` the server has already moved the player and the connection needs resynchronization. Offering another teleport at this point can duplicate a gameplay action.

## Build together

An authoritative Script owns construction edits. In multiplayer, have the local input handler send a build action. On the server, resolve its authenticated sender, validate their reach, target, domain and permission, then edit the grid. A client can draw a preview or read an installed cell. The server chooses which construction and terrain data each connection receives. Waiting for the grid Instance only establishes its identity.

```luau
local function DescribeCell(Grid, Cell)
	if not Grid:IsRegionAvailable(Cell, Cell + Vector3.new(1, 1, 1)) then
		return "Waiting for construction"
	end
	local Block = Grid:GetBlock(Cell)
	return if Block then Block.Definition else "Air"
end
```
