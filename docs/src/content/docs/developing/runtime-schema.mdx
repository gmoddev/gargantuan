---
title: Runtime Schema
description: The canonical native class and reflection schema implemented by Gargantuan.
---

Gargantuan's `RuntimeSchemaRegistry` is the authoritative metadata source for
native Instance classes. Generated definitions flow into this registry;
existing reflection APIs adapt the same registered objects rather than keeping
a second class table.

## Implemented foundation

Each native definition has a deterministic 128-bit `SchemaId`, an `Engine`
namespace, human-facing class name, canonical qualified name, definition
version, native provenance, stable base identity, properties/signals, and
methods. The ID is independent of addresses, hierarchy, startup randomness,
and registration order. Its deterministic text form is 32 hexadecimal
characters, and the zero value is invalid.

Property metadata carries reflected value type, native readability and
writability, persistence, replication, editor editability, write authority,
domain sets, required capabilities, validation, and declaring class identity.
Methods carry declaring identity plus invocation domain/capability metadata.
Current method grants preserve existing behavior.

Project serialization and replication selection consume their respective
policies from these canonical property objects. Persistence no longer has a
parallel boolean selector that could diverge.

The registry provides lookup by stable ID, native type, and qualified or legacy
unqualified name. Observable enumeration is sorted by canonical name. Public
lookups return immutable definitions. Validation fails on duplicate IDs/names,
invalid or cyclic inheritance, invalid member ownership/types/access, and
conflicting members.

## Registration lifecycle and freeze

Native startup follows an explicit sequence:

```text
Bootstrap
  -> NativeRegistration
  -> CoreRegistration
  -> ExternalRegistration
  -> Validation
  -> Frozen
  -> Runtime
```

Core and external registration are reserved no-op phases in the current
implementation. PreRun and custom definitions are not implemented.

Generated native definitions are deterministic bootstrap inputs to a hidden,
mutable candidate registry. The candidate is validated as a whole, including
inheritance and flattened member views, before it can freeze. Only a frozen
candidate can be atomically published as the active registry. If registration,
validation, freeze, or generation assignment fails, the candidate is discarded
and the previous active registry and generation remain unchanged.

The active registry is immutable. Registration after freeze, repeated freeze,
and lifecycle phase jumps fail with diagnostics. Normal runtime construction
requires the schema to have reached `Runtime`, so no normal `Instance` can be
constructed against a partially registered schema.

Each successful complete publication receives a session-local unsigned 64-bit
registry generation. Zero is invalid and the first generation is 1. Successful
replacement increments it; failed candidates do not. The counter fails closed
at its maximum rather than wrapping. Registry generation exists for cache
invalidation and is separate from the persisted semantic
`DefinitionVersion` on each schema.

`InstanceClassDefinition` and `InstanceClassRegistry` remain as source-compatible
native reflection names, but they are an alias and adapter over the runtime
schema. Existing `IsA`, property lookup, snapshots, journals, replication,
EditorHost, and mutation paths retain their contracts.

Schema metadata is descriptive. Namespace, provenance, class name, and domain
never imply privilege. Capability checks remain enforced by native reflection
dispatch and `MutationGateway`.

## Not implemented yet

PreRun, Core Luau registration, custom definitions, extensions, enums,
migrations, packages, plugins, Studio schema discovery, and generated Luau
typing remain future architecture. The lifecycle has reserved phases for later
loaders, but no runtime Luau environment has schema-definition authority.

The next schema milestone is attributes and tags as an end-to-end feature on
the frozen schema.
