---
title: Runtime Schema
description: Gargantuan's canonical frozen class, custom-enum, and class-extension schema.
---

`RuntimeSchemaRegistry` is Gargantuan's one authoritative schema. Native
native and project classes, project enums, and project class extensions are tagged definitions in the same registry;
legacy class reflection is a class-only adapter over those frozen definitions.

## Stable identity

Every definition has a deterministic 128-bit `SchemaId`. Native classes,
custom classes, custom enums, and extensions use four separate identity domains, so IDs do not depend on pointers,
startup randomness, hierarchy, registration order, or registry generation.
The wire form is 32 lowercase hexadecimal characters and zero is invalid.

Classes retain inheritance and reflected property/method metadata. A custom
enum contains namespace, name, canonical name, nonzero definition version,
`Game` provenance, and unique ordered name/numeric-value items. Enum values
carry `{EnumSchemaId, DefinitionVersion, ItemValue}`; an integer or display
name alone is never authoritative identity. An extension has its own stable ID
and version, stores a resolved target class `SchemaId`, and owns ordered
namespaced declarative properties without changing the target class identity.
A custom class is still a class definition. It stores a stable base class ID,
an engine-owned construction policy and native host ID, and ordered declarative
properties. Definition version is compatibility metadata and never contributes
to its `SchemaId`.

## Registration lifecycle

```text
Bootstrap
  -> NativeRegistration
  -> CoreRegistration
  -> PreRunRegistration
  -> Validation
  -> Frozen
  -> Runtime
```

Registration builds a hidden mutable candidate. A project may provide
`.gargantuan/prerun.luau`; the native bootstrap selects it and executes it
before world construction. The dedicated `PreRun` domain is not authority by
itself: the native registration boundary requires the explicit `DefineSchema`
capability and the active candidate phase.

PreRun exposes sandboxed base, math, string, table, UTF-8, and only this narrow
facade:

```lua
Schema:RegisterEnum({
    Namespace = "Game",
    Name = "CombatState",
    Version = 1,
    Items = {
        Idle = 0,
        Attacking = 1,
        Blocking = 2,
    },
})

Schema:RegisterExtension({
    Namespace = "Game.Combat",
    Name = "CombatProperties",
    Version = 1,
    Target = "Engine.BasePart",
    Properties = {
        Damage = { Type = "Integer", Default = 0 },
        Team = { Type = "String", Default = "" },
    },
})

Schema:RegisterClass({
    Namespace = "Game",
    Name = "CombatFolder",
    Version = 1,
    Base = "Engine.Folder",
    Properties = {
        Health = { Type = "Integer", Default = 100 },
        Faction = { Type = "String", Default = "" },
    },
})
```

It has no DataModel, filesystem, process, OS, debug, require, network, Studio,
renderer, or registry-pointer access. Current limits are 256 KiB source, 250 ms
execution, 16 MiB VM allocation, 64 enum definitions, 256 items per enum, 64
extension definitions, 64 custom class definitions, 64 properties per extension
or custom class, 16 inheritance levels, 4 KiB per encoded default,
100-byte UTF-8 identity/item/property names, and 64 KiB aggregate registration payload.
The source path is canonicalized beneath the selected project root, symlink
escapes are rejected, and the file is read through a fixed maximum-plus-one
buffer so concurrent file growth cannot turn the size check into an unbounded
read.

The complete candidate validates before freeze. Any collision, malformed
definition, script error, or budget failure aborts all project definitions and
does not advance the active registry generation. The prior frozen registry, if
one exists, remains coherent. Post-freeze registration fails even with the
capability. Aggregate payload accounting is enforced again by the canonical
registry rather than trusting only the Luau facade.

Registry generation is a session-local unsigned 64-bit cache selector. It is
separate from per-definition semantic version and is not part of `SchemaId`.

## Wire and Studio discovery

The closed `WireValue` model includes a `SchemaEnum` value with stable enum ID,
exact definition version, and signed 32-bit item value. Materialization fails
on malformed/missing IDs, wrong definition kind, incompatible version, or
unknown item. General migrations are not implemented, so exact version equality
is the current policy. Attributes still reject enum values and Tags are
unchanged.

EditorHost `GetSchema` exposes schema-discovery version 5, active registry
generation, and deterministic class/enum/extension definitions while retaining its old
`Classes` DTO. Studio caches immutable definitions by `SchemaId` plus
definition version and selects the active set by registry generation. Studio
has read-only discovery; it cannot register or modify definitions.

Native `InstanceProperty` metadata is part of those class definitions rather
than a parallel editor schema. Supported properties declare semantic datatype,
closed `WireValue` type, effective Studio access, category, optional finite
range and editor hint, compound identity, native enum type/items, or nullable
object-reference class constraints. `SetProperty` requires exact object-class
and declaring-class schema identity/version for these native edits. EditorHost
validates through `MutationGateway`, and Studio reconciles only from journal
state. Object references are described accurately but remain read-only.

Extension values are sparse per-Instance runtime state distinct from Attributes.
Missing overrides read the frozen default. Each Instance is limited to 128
physical overrides and 32 KiB of aggregate extension state. Luau reads/writes by
extension plus property identity, and writes require `MutateDataModel` through
`MutationGateway`; `DefineSchema` grants no runtime authority. Persistence
version 4 and snapshot/journal version 6 carry extension ID, exact definition
version, property identity, and typed value. Target, kind, version, and type
mismatches fail safely. The initial property domain is Boolean, signed 32-bit
Integer, finite Number, and bounded UTF-8 String.

Custom classes use the same scalar property domain and sparse storage policy.
The runtime object carries its actual custom class `SchemaId` separately from
the engine-owned C++ host implementation. `ClassName`, reflection, `IsA`,
persistence, snapshots, replication, and Studio resolve semantic identity from
the frozen class definition. The first native policy permits only data-only
subclasses of `Engine.Folder`; physics-bearing, service, abstract, and internal
classes remain forbidden. Custom-on-custom inheritance is supported within the
same candidate, including child-before-parent registration, with whole-candidate
cycle, depth, constructibility, and inherited-member collision validation.

Missing custom overrides read the declaring class default. Each Instance is
limited to 128 physical custom-property overrides and 32 KiB of encoded custom
state. Setting the default removes storage. Values remain distinct from
Attributes and extension state and use ordinary reflected property mutation
through `MutationGateway`; `DefineSchema` still grants no runtime authority.
Persistence version 4 and snapshot/journal version 6 carry exact class and
declaring-class `SchemaId` plus definition version. Legacy persistence versions
remain name-based only for native classes, and exact version mismatch fails
rather than falling back to a native base.

## Compatibility and deferred work

Native class IDs, `IsA`, member lookup, construction, serialization,
snapshots/journals, loopback replication, mutation security, rendering, and
viewport behavior remain compatible. Built-in native `EnumItem` remains a
compatibility system; project enums use the canonical schema and no second
custom-enum registry exists.

Core Luau registration, native-enum unification, enum globals/generated types,
enum-valued Attributes or schema properties, object-reference schema
properties, project behavior callbacks/hooks, migrations, packages, plugins,
additional custom-subclassable native hosts, and component composition are
deferred.
