### Studio

The production Studio application is now developed as separately authored,
private code. It communicates with the MPL-2.0 engine through the public
[EditorHost process boundary](./editor-host/). The original in-engine prototype
was removed; its MPL-2.0-covered implementation remains available through Git
history and is not source material for the private application.

Engine-side editor interface progress:

- [x] Versioned EditorHost handshake and capability discovery
- [x] Non-executing project open
- [x] Schema, snapshot, and ordered journal access
- [x] Scalar property mutation through the authoritative gateway
- [x] Initial offscreen viewport capture, ObjectId picking, and camera commands
- [x] Negotiated bounded shared-memory frame ring and drop-old backpressure
- [ ] Continuous native presentation loop with measured 30/60 FPS pacing
- [ ] Restricted Luau Studio UI runtime and explicit editor services
- [ ] Save, play-session, and transaction interfaces

Projects will initially have:

### Native development workflow

This sequence follows the existing authority, EditorHost, and Studio boundaries.
Later phases must not be pulled forward by exposing filesystem or MCP access in
Player/server runtimes.

#### 1. Contracts and identity

- [ ] Accept a durable authoring-identity design distinct from session-scoped `ObjectId`
- [ ] Specify bounded source revisions, hashes, synchronized-base retention, and stale-write behavior
- [ ] Specify versioned, recoverable mapping metadata with project-root-confined paths
- [ ] Specify source transaction, journal, undo/redo, save, deletion, rename, and recovery semantics
- [ ] Define explicit Studio script-sync and DevBridge capabilities and denial behavior

#### 2. Manual synchronization foundation

- [ ] Add bounded authoritative source read/write commands with expected revisions
- [ ] Extend EditorHost for source operations, transactions, and structured sync errors
- [ ] Support manually mapping an existing script to a project-relative file
- [ ] Implement explicit one-shot Studio-to-disk and disk-to-Studio synchronization
- [ ] Prove atomic disk replacement, cancellation, rollback, and crash recovery

#### 3. Automatic two-way synchronization

- [ ] Add stable filesystem observation with debounce and rename/move detection
- [ ] Propagate clean one-sided edits in both directions without watcher feedback loops
- [ ] Preserve script authoring identity across file and Instance rename/move operations
- [ ] Define explicit create/delete behavior before enabling automatic hierarchy mirroring

#### 4. Conflict safety

- [ ] Detect concurrent changes from the last mutually synchronized base
- [ ] Persist base, Studio, and external versions behind bounded conflict retrieval
- [ ] Add generation-safe conflict identities and atomic conditional resolution
- [ ] Test stale conflicts, retry/restart recovery, large sources, encoding, and line endings

#### 5. Studio authoring surfaces

- [ ] Add the Studio-only `DeveloperService` facade over native coordination operations
- [ ] Build sync status, mapping, suspension, resync, diff, and three-way conflict UI
- [ ] Integrate source changes and resolutions with Studio transactions, undo/redo, and save
- [ ] Define a compatibility/import path for existing `FileLink` or Rojo project layouts without retaining their authority model

#### 6. Optional MCP DevBridge

- [ ] Add an opt-in authenticated, project-scoped Studio DevBridge with bounded sessions and requests
- [ ] Expose narrow revision-aware script inspect/read/write/sync/conflict tools
- [ ] Route MCP and Studio UI through the same development coordination core
- [ ] Ship agent guidance for expected-revision writes and explicit conflict handling
- [ ] Prove the engine, Player, and production server have no MCP or host-sync dependency or exposed service

#### 7. Hardening and exit criteria

- [ ] Add path traversal, symlink/junction escape, stale identity, malformed metadata, and capability-denial tests
- [ ] Bound watched roots, mappings, queued events, source bytes, conflicts, retained bases, requests, and timeouts
- [ ] Add structured `[Studio:ScriptSync]` and `[Studio:DevBridge]` diagnostics without logging source or secrets
- [ ] Demonstrate clean Studio edits, clean external edits, simultaneous edits, each resolution mode, rename/move, delete, restart recovery, and stale MCP writes end to end
