completed implementation. Existing version headings are planning buckets, not

## Subsystem status

Implementation and qualification are independent. **Foundation implemented**
means the stated baseline exists, not that the whole subsystem has shipped.
**Not assessed here** means this review did not establish a subsystem-wide
qualification verdict; it does not invalidate existing scoped tests or reports.
**Qualified** must always identify the revision, platform/workload scope, and
acceptance evidence. Blocked, deferred, and superseded describe planning state.

## Future architecture tracks

These tracks have separate priorities; they are not one global queue. The
[full proposal](../../../../../devdocs/FutureArchitecture/ArchitecturalDisciplineAndSubsystemBoundaries.md)
contains ownership rules, rejection behavior, resource units, and acceptance criteria.

### Architecture enforcement

- [ ] Architecture 0A: extract a machine-readable target/include/dependency graph
- [ ] Architecture 0B: declare allowed directions and forbidden subsystem edges
- [ ] Architecture 0C: report violations, then enforce forbidden-edge CI
- [ ] **Partial — Architecture 0D:** ~~separate GNS transport and packaged host targets~~; verify their transitive boundaries against the graph and extract neutral protocol/codecs and renderer-neutral publication targets
- [ ] Architecture 0E: progressively isolate remaining targets where ownership benefits justify the change
- [ ] Audit canonical schema coverage for methods, signals, services, arguments, returns, docs, Luau types, and MCP introspection; extend the existing registry

### Foundation 3L closure, then 3M

- [ ] Close 3L's current correctness, service, resource, and qualification gates; passing the GNS sanitizer gate alone is insufficient
- [ ] Foundation 3M: trusted default-space residency demand policy over the existing 3L lifecycle
- [ ] Bound coarse queries, candidates, retained policy state, and request/release deltas
- [ ] Add semantic priority, deadlines, deterministic distance/cost ties, enter/leave hysteresis, and bounded trusted movement lookahead
- [ ] Reject stale policy revisions and prove scale, cancellation, acquisition deduplication, and Character/Remote service preservation

3M owns demand only. 3L owns content lifecycle, 3E owns relevance, and 3J owns
accepted materialization/`Known`. Do not introduce a second streaming lifecycle.

### Network security and hardening

- [ ] **P0 before public untrusted hosting:** bounded PendingAdmission and short-lived signed server/session-bound join grants, expiry/replay checks, and key rotation
- [ ] Gate Player, Character control, 3E/3J state, Remote gameplay state, content pins, and capabilities on successful admission
- [ ] Keep GSES protocol/schema/build compatibility validation independent of control-plane identity
- [ ] Qualify untrusted public hosting after admission is implemented
- [ ] **P2 after reliable-service stabilization:** bounded receiver-normalized semantic anti-entropy; mismatches enter normal complete 3J recovery groups and never advance `Known` directly

### Performance and asset residency

- [ ] **Partial:** ~~existing content/planning/selection/transport budgets and diagnostic counters~~; inventory finite resource/service envelopes across discovery, derivation, preparation, encoding, scheduling, transport, application, and cleanup/recovery
- [ ] Extend bounded subsystem-owned CPU, retained-byte, allocation, and residency attribution; use static tags, not per-object or user-string identities
- [ ] Asset 2B: canonical/decoded/GPU/physics/animation bytes, consumers/pins, last use, and load/eviction counts before normative general eviction policy
- [ ] Investigate an immutable same-tick 3H/3K read epoch only as justified infrastructure
- [ ] Add allocator hooks or 3E worker derivation only after measured need, serial/parallel crossover, and Amdahl headroom

### Studio provenance and trust

- [ ] Add engine-assigned author provenance and generation-safe author leases over the existing authoritative history
- [ ] Extend host-created capabilities with scoped plugin grants, explicit project trust, consent, and revocation
- [ ] Design bounded staged atomic external-author transactions only if a concrete workflow requires them; current recording groups committed edits and does not promise rollback
- [ ] Keep one ordered undo history; collaborative/selective undo remains a separate design

### Large worlds and continuous fuzzing

- [ ] Validate default-space 3M policy before semantic SpatialRegion, region-local physics/topology, and portals
- [ ] Keep semantic region identity separate from internal SpatialSpaceId; portals provide candidates to existing residency/relevance owners
- [ ] Define independent render, replication, spatial-query, audio, interaction, and AI traversal budgets
- [ ] **Partial:** ~~network protocol fuzz targets~~; expand coverage-guided fuzzing and retained regression corpora by risk across content, snapshot/journal, persistence, package/artifact, bounded importers, then future admission/topology parsers

Generic prediction extraction waits for a second consumer. Schema registration,
capabilities, validated publication, Character reconciliation, and Studio history
are existing foundations to extend, not new replacement frameworks.
