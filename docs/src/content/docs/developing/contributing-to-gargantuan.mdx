## Find the owner

| Paths | Responsibility |
| --- | --- |
| `src/classes`, `src/services`, `include/gargantuan` | Native Instance, service and boundary implementation |
| `assets/classes`, `assets/services`, `tools/classgen.luau` | Canonical declarations and generated reflection |
| `src/runtime`, `src/reflection` | Identity, mutation, journal, jobs and schema lifecycle |
| `src/scripting`, `assets/runtime`, `assets/stdlib` | Luau integration and Engine-shipped policy |
| `src/render`, `src/physics`, `src/network` | Consumer and backend boundaries |
| `src/editor` | Engine-owned EditorHost protocol and authoring state |
| `tests`, `.github/workflows` | Regression, workloads and qualification contracts |
| `docs/src/content/docs`, `devdocs`, `docs/adr` | User guides, contracts and decisions |

The [Engine, Studio and Node map](../engine-studio-node/) identifies repository
owners. Start with existing issues and accepted decisions for substantial
architecture work. Check [known issues](../../../../../KNOWN_ISSUES.md) before
claiming a fix.

## Coding and change conventions

Use **PascalCase** for applicable new identifiers. Preserve existing public API
spelling and established local conventions; `self = setmetatable({}, ...)` is
the narrow project exception. Name get-or-create helpers `GetFolder` or
`GetObj`. Prefer log prefixes such as `[Combat:MedicalSys]`.

Preserve Main-owned mutation, generation-safe identity, immutable publication,
capability checks, bounded failure and subsystem ownership. Explain non-obvious
invariants in useful comments. New authority, protocols or registries require
explicit architectural review. Update current contracts and usually an ADR
alongside architecture changes.

Use isolated worktrees for concurrent campaigns. Preserve unrelated edits and
stage explicit intended paths. Follow cooperative worker policy for heavy
builds; documentation-only checks do not reserve native workers.

## Verify and submit

Use the [build guide](../working-on-gargantuan/). Run focused tests covering
behavior, rejection, bounds and lifecycle. Required native CI runs the complete
configured matrix. Documentation checks cover links, navigation, source paths,
declarations and example syntax.

Performance claims need exact source/binary/fixture identities, configuration,
raw distributions and the existing acceptance contract. Headless or simulated
PASS does not certify a physical GPU, provider deployment or F1. Keep failed
measurements under their original identity.

Describe concrete behavior, ownership/lifecycle impact, API/wire compatibility,
security/capabilities, affected decisions/docs, tests and limits. Draft
incomplete or unqualified work. This documentation campaign requires the pending
Engine integration to be reconciled at its exact `main` SHA before merge.
