The table routes you to the native binding rather than guessing full Roblox datatype compatibility. A registered userdata **without** an `OpenLib...` entry has no separate constructor global.

## Verified construction and use

`Vector3.new(1, 2, 3)` returns Gargantuan's three-component Luau vector; `Vector2.new(1, 2)` returns native `Vector2` userdata. `Vector3.zero`, `Vector3.one`, axis constants, `Magnitude`, `Unit`, `:Dot`, `:Cross`, and `:Lerp` are implemented in `LibVector3.cpp`. `CFrame.new()` is identity; supported overloads take one position vector, two position/target vectors, or three numeric position components. Other argument counts raise `unsupported constructor`. `CFrame.Angles(Rx, Ry, Rz)` takes three numeric rotations. `Random.new()` or `Random.new(Seed)` constructs a VM value; check its binding for the exact method set before porting Roblox code.

`RaycastParams.new()` creates mutable VM-local userdata with `FilterType` (`Enum.RaycastFilterType.Exclude` by default), `FilterDescendantsInstances` (a copied array of live Instance roots), `CollisionGroup` (0–15), `CollisionMask` (0–65535), and `IncludeTerrain` (`false` by default). Filter assignment rejects holes, nonnumeric keys, dead/non-Instance values, and more than 128 roots. A query can also reject a root from another `WorldRoot`. See [world queries](../world-and-rendering/) and the [math/filter/signal example](https://github.com/gmoddev/Gargantuan/blob/main/docs/examples/math-filter-signal.luau).

`Signal.new()` creates a user signal. `:Connect(Callback)` and `:Once(Callback)` return a `SignalConnection` with read-only `Connected` and `:Disconnect()`. `:Wait()` suspends the caller until fired, where yielding is allowed. `:Fire(...)` works on a **user-created** signal; trying to fire an engine event raises an error. The connection and callback are VM-lifetime state, not persisted data. Signal callbacks and waits restore the context in which they were registered, even when an engine event fires later.

`Animator:LoadAnimation` returns an `AnimationTrack` value with playback controls and `Ended`; it cannot be constructed by naming a class with `Instance.new`. Destroying its owner invalidates retained tracks. [Input, GUI, and media](../input-gui-and-media/) covers the asset and owner requirements.

## Globals, scheduling, and failure

`game` is this VM's `DataModel`. `print(...)` and `warn(...)` produce one bounded diagnostic record per call: at most 64 arguments, 512 UTF-8 bytes per formatted argument, and 2,048 bytes per record with truncation. Formatting does not call your userdata's `__tostring`; messages may be dropped from bounded Play/Studio output queues under pressure.

`require` resolves instance-backed `ModuleScript` source through the requiring Instance path, with the engine's `@game` alias. Missing modules, invalid module targets, compile failures, and module errors raise Luau errors. It does not grant arbitrary filesystem access or a general project alias system. Use `pcall` when an optional module can be absent.

`task.spawn`, `task.defer`, `task.delay`, and `task.wait` use the runtime scheduler and retain the originating script security context. Deferred and scheduled work share a 65,536-entry queue limit. `task.delay` and `task.wait` reject NaN durations. `task.wait` can reject a handler context that disallows yielding.

`task.cancel(Thread)` returns `true` when it removes a suspended coroutine's pending scheduler entries, including a later deferred callback in the current step. The scheduler releases its references immediately. The call returns `false` for a running, finished, already canceled, or otherwise unowned coroutine. A pending signal wait or RemoteFunction continuation keeps its independent lifetime. Canceling scheduled work leaves the coroutine's Luau state intact.

`task.synchronize` and `task.desynchronize` are unimplemented. Native type errors, invalid values, permission denials, and resource limits are Luau errors. Use `pcall` when an error is expected.

Ordinary gameplay gets a default 250 ms wall-clock budget each time the
Engine enters Luau. Nested calls inherit the remaining time. A long loop can
raise a catchable `[Runtime:ExecutionBudget]` error at a VM safepoint. Split
long-running script work across frames. A native binding must return before
the VM can sample the clock again. Trusted offline hosts can configure the
interval or disable it with zero. Hostile-code isolation, memory limits and
a total frame budget require additional controls.

An error in a scheduled task reaches the runtime diagnostic sink with the
`[Runtime:Task]` prefix and up to 1,024 bytes of error detail. Play can show
the Luau chunk name and line number carried in that error. A failed task
retires its own scheduler reference.

The VM's per-Script `script` global remains bound to its originating Script through a yield. Finishing the initial Script releases that coroutine's root after its active `lua_resume` returns, while separately scheduled tasks, signal callbacks, and Remote requests keep their own roots. Engine shutdown stops new callback admission and cleans tracked Scripts; an active native Lua call keeps its VM alive only through its return or error boundary. These lifetime rules do not add capabilities or make a retained Instance valid after its DataModel is destroyed.
