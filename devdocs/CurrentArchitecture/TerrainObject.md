# Workspace terrain ownership and field reads

This document covers the Terrain shell and read contract in the Terrain Foundation 1 candidate. The existing Runtime schema, DataModel identity scope, authoritative Main domain and project graph contracts govern the implementation. The separate terrain field document owns the scalar representation and its native mutation semantics.

## Ownership

Resolving the canonical DataModel Workspace establishes one native Terrain child under that Workspace. Loaded authoring projects resolve the service before publishing revision 1. Engine startup resolves the same service for runtime worlds. `FindService` and subsequent `Workspace.Terrain` reads observe established state. Other WorldRoots, detached Workspace objects, and preview roots have no terrain by default.

The Terrain Instance has ordinary scoped identity, ancestry and lifecycle signals. Its Workspace owns it through parent-child lifetime, and the Terrain shell owns the native Field allocation. Only native Workspace setup constructs it. Cloning, reparenting, direct destruction, editing inherited identity properties, assigning attributes or extension overrides, adding tags, and inserting child Instances are rejected. `Workspace:ClearAllChildren()` preserves Terrain and retains its ordinary behavior for other children. Workspace teardown retires the terrain identity and releases the Field. Existing Instance wrappers cannot retain field pages after teardown. Immutable snapshots owned by pending native work have their own bounded lifetime and must be invalidated by the consuming scheduler.

The shell has no saved Instance payload. JSON and GAS omit it from the authored hierarchy, and opening a project produces a fresh scoped identity. Saved or replicated object references cannot target the local shell. The project and package pin a canonical GTMF manifest and its GTCH artifacts outside the ordinary Instance document. Package bootstrap retains the canonical Workspace and establishes its terrain locally. [Persistence qualification](../Validation/TerrainPersistence.md) · [Multiplayer admission](../../docs/adr/TerrainNetworkBootstrap.md)

EditorHost's authoring snapshot includes the current Terrain Instance so it can be selected and inspected. Structural snapshots and peer relevance exclude it. Shell synthesis and retirement do not advance the authored revision or write structural journal records. Each runtime can establish its own shell without accepting a second network-created Terrain Instance. Terrain chunk/field data requires a separate authoritative readiness and synchronization contract.

## Read API

`Workspace.Terrain:GetGridInfo()` returns readonly metadata for a live Terrain owned by the current VM's DataModel. `FieldAvailable` indicates whether the current runtime has authoritative local field access. `SampleSpacing` is in world units and `Revision` is an exact unsigned decimal string. Those fields remain private to the authoritative runtime during multiplayer. Studio can select sample spacing when creating a project. `MaximumSampleCoordinate` and `MaximumRegionSamples` describe the native read boundary. The qualified physics and renderer extent is narrower than the sample address range.

`Workspace.Terrain:ReadRegion(Min, MaxExclusive)` takes two Vector3 lattice coordinates with finite integer components. The box is half-open on every axis, with at least one sample and at most 4,096 samples. It returns a newly allocated Luau buffer and the exact committed field revision. Samples are interleaved signed 16-bit density and unsigned 32-bit material in little-endian order, with X fastest, then Y, then Z. For empty authoritative locations the sample is density 32,767 and material 0. An unavailable field, stale world, capability denial, invalid coordinates or excess sample count fails before returning a buffer. Reads run in Main and require `ReadDataModel` and an exact live DataModel match. Network-client reads fail explicitly instead of synthesizing empty terrain from an unsynchronized field. The public read results describe the field and do not certify render or collision readiness.

The existing [Foundation regression suite](../../tests/FoundationTests.cpp) includes scope/bootstrap, authored-versus-structural snapshots, JSON reopen, ownership denials, packed buffer reads, unavailable client reads, and teardown with a retained Instance wrapper.

## Authoritative runtime edits

The Engine constructs one scheduler and one provider stage for the live Workspace. `EditingAvailable` is true for authoritative scripts while the terrain runtime is healthy. The public edit path is available in offline gameplay and the qualified loopback Development server profile. The gateway checks Main, trusted gameplay authority, exact terrain and world identity, and capability before admitting an edit. Each edit snapshots its inputs and required field dependencies. It publishes at the simulation safe point after provider preparation. The multiplayer server delivers the committed regional revision through the same collision-readiness workflow as travel. [Playable multiplayer sample](../../samples/TerrainQuarry/README.md)

`FillBall(Center, Radius, Material)`, `RemoveBall(Center, Radius)`, `PaintBall(Center, Radius, Material)`, and `FillBlock(Center, Size, Material)` accept finite world-space input. `FillBlock` is axis-aligned. Material IDs are nonzero uint32 values for solid samples. `WriteRegion(Min, MaxExclusive, Samples, ExpectedRevision?)` validates the same packed format as `ReadRegion` before queuing work. `ClearRegion(Min, MaxExclusive)` replaces the bounded lattice box with air. `SmoothRegion(Min, MaxExclusive, Strength)` admits one pass at a strength from zero through one. Region operations accept at most 4,096 samples. All operations are subject to shared worker, chunk and provider bounds. `ReadRegion` followed by `WriteRegion` can copy a bounded lattice volume to another aligned position.

Each admitted request returns an opaque string ticket scoped to the current field lifetime. `GetEditStatus(Ticket)` returns `Pending` until terminal, then the committed revision and `CollisionReady` on a successful install. Failed or canceled work returns its terminal status without readiness. Failed work can include a `Diagnostic` with remediation guidance. `ReopenCapacityExceeded` means the proposed edit would exceed the offline startup source or contour capacity. `CancelEdit(Ticket)` requests cancellation before commit. The latest 128 tickets are retained per live world. A query for an expired, foreign, or unknown ticket returns nil. Writes with an expected revision revalidate it immediately before publication. GPU presentation follows its own publication and readiness boundary. See the [offline Luau sample](../../samples/TerrainFoundation1/README.md).

## Collider query projection

`RaycastParams.IncludeTerrain` defaults to false and preserves BasePart-only query results with the existing options. Opting in lets an installed terrain collider resolve to the canonical Workspace Terrain as the `Instance` of ray and shape hits. Overlap queries retain their sorted `Parts` array and include one optional `Terrain` field when any accepted terrain collider overlaps. A Terrain result does not occupy a slot in the BasePart result limit. Include and exclude root filters match Terrain through the same WorldRoot descendant check and apply to its installed bodies as a group within the existing collider limit. The filter sees terrain only after the scheduler installs an active collider stage.

The provider reverse lookup interprets generation-qualified body identity through the stage's installed collider map. Internal chunks and shapes have no public Instance identity. Tie resolution continues to use semantic ObjectId across different objects, then uses the terrain chunk coordinate for ties within Terrain. A query attempted during an unfinished provider stage returns an explicit unavailable error. Native `WorldRaycastResult::Instance` remains BasePart-typed, and native consumers opting in can use `GetHitInstance()` to inspect either semantic owner.
