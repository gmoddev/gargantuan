## Current contracts and gaps

| Area | Confirmed path and evidence | Consequence for this design |
| --- | --- | --- |
| Object lifetime | DataModel owns the live graph, journal and registry scope. Engine binds descendants for script, animation and audio registration. `Engine::Destroy` disconnects observers, shuts down script/runtime services, releases GUI, calls renderer Destroy and destroys its WorldRoot. [Engine](../../../src/Engine.cpp) · [Core invariants](../../../docs/invariants/Core.md) | Retain the app's resources outside that destructor. Scope handles by app/session generation and graph. Rebuild the world from its committed representation. |
| Packaged startup | Player calls BootstrapPackagedRuntime, validates target/audience and package trust. Offline loads a packaged world, composes local fully resident content and Engine. Network startup polls/steps GNS until GameSession supplies the trusted client graph, hydrates locally admitted code, then constructs a client Engine. Server binds separately without graphics or audio output. [Player](../../../src/host/player/PlayerHost.cpp) · [Server](../../../src/host/server/ServerHost.cpp) · [Distribution ADR](../../../docs/adr/Runtime-Distribution-1.md) | Existing role and manifest admission can be reused. The synchronous handshake and fully resident constructor loop need a responsive startup path for opt-in applications. There is no general in-process menu/replacement loop here. |
| Local and server scripts | ScriptEngine opens Luau against a DataModel. Script::Step selects client/server context from RunContext. Offline admits normal scripts of both contexts, subject to template/service rules. Network client admits client code; server admits server-side code. Owner GUI code has additional provenance and ownership checks. Ordinary execution, nested requires and deadline enforcement are already implemented. [ScriptEngine](../../../src/scripting/ScriptEngine.cpp) · [Script](../../../src/classes/Script.cpp) · [Script security](../../CurrentArchitecture/ScriptSecurity.md) | Package and activate a single designated client entry, restrict app services/operations natively, keep modules and coroutine references VM-local. Ordinary scripts keep their existing execution rule. |
| Player/GUI | Offline Engine initializes LocalPlayer and starts shipped bindings/controller/camera. Network Engine requires a trusted LocalPlayer before attachment. Players provisions StarterGui roots to owner-only PlayerGui, with fresh references/IDs, selective ResetOnSpawn and filtered client script hydration. GuiRuntime also admits legacy ScreenGui roots. Preview has separate noninteractive mode. [Players](../../../src/services/Players.cpp) · [PlayerGui contract](../../CurrentArchitecture/PlayerGui.md) · [GUI runtime](../../../src/gui/GuiRuntime.cpp) | Reuse ScreenGui, controls, Activated and ViewportFrame. Keep the menu closure out of StarterGui delivery. Preview the designated root using the existing renderer and an explicit projection filter. |
| Frame pipeline | Engine::Step drains mutations and content, samples delta and increments simulation tick, steps tweens, fires PreSimulation, steps Workspace then attached regions, updates camera, fires PostSimulation and PreRender, applies animation/root motion, reconciles GUI, renders, then steps scripts/audio. [Engine](../../../src/Engine.cpp) · [RunService schema](../../../assets/services/RunService.luau) | A zero delta still runs callback, mutation and tick paths. Skipping all Step work starves interactive services. Introduce explicit simulation and service admission. |
| Scheduler and callbacks | ThreadEngine schedules against steady time (or injected development clock), retains security context and drains due timers and deferred work. Combined queued entries cap at 65,536. LibTask spawn resumes immediately. Signal Wait/Connect also enter Luau outside the delayed queue. Root debugger injects a paused-time-adjusted engine/task clock. [ThreadEngine](../../../src/scripting/ThreadEngine.cpp) · [LibTask](../../../src/scripting/LibTask.cpp) · [Signal](../../../src/datatypes/Signal.cpp) · [PlaySession](../../../src/editor/PlaySession.cpp) | Reuse clock injection and execution budgeting. Extend admission/retirement to every entry edge and impose an aggregate drain budget. Debugger parking deliberately suppresses input. |
| Interaction and display | Engine routes UserInputService before GUI, then InputService with GUI-consumed information, then free camera. Shipped ActionMap, character and camera modules use their own subscriptions. Native relative capture, focus/IME and immutable GUI publication exist. ViewportFrame supports a local presentation subtree and descendant Camera. [Input actions](../../CurrentArchitecture/InputActions.md) · [ViewportFrame](../../../src/classes/ViewportFrame.cpp) · [GUI tests](../../../tests/GuiFoundationTests.cpp) | A full-screen button cannot suppress raw listeners by itself. Insert capture before all gameplay consumers and preserve presentation generation on hit testing. |
| Audio, tween, animation | AudioRuntime mixes voices into backend buffers; AudioMixService exposes local master/category gain and mute. TweenService runtime steps before simulation callbacks. AnimationRuntime evaluates poses and exports root-motion requests into simulation. [Audio](../../../src/audio/AudioRuntime.cpp) · [AudioMixService](../../../assets/services/AudioMixService.luau) · [Animation](../../../src/animation/AnimationRuntime.cpp) | Budget audio tail and separate sample clocks. App-local tweens/presentation motion can advance in another scope. No general gameplay particle emitter/scheduler was identified in the inspected public class set. |
| Network and world readiness | GameSession owns accepted peer, authoritative Player creation, replication, LocalPlayer and control binding. Terrain/grid installs add readiness fences. Hosts poll transport and pass Engine simulation tick into GameSession::Step after attachment. Starting and running have different tick sources. [GameSession](../../../src/network/GameSession.cpp) · [GameSession tests](../../../tests/GameSessionTests.cpp) · [Spatial package test](../../../tests/SpatialConstructionPackageSession.py) | Polling alone cannot supply every handshake/lease/scheduler tick while global simulation is frozen. Keep a service ordinal. A client's input lock and authoritative pause need different observable state. |
| Persistence | Engine composes a provider before gameplay, handles server-only operations and bounded main-thread delivery. Memory/SQLite/optional Node providers support distinct guarantees. UnknownOutcome is possible after dispatch. Studio supports disposable/local project-specific providers. Default packaged Player config does not provision a user world-slot catalog. [Gameplay persistence](../../CurrentArchitecture/GameplayPersistence.md) · [PlaySession](../../CurrentArchitecture/PlaySession.md) | Do not make Node necessary for slots. Keep local catalog/selection, authoritative writes and local preferences distinct. Session exit needs a commit and recovery contract. |
| Spatial domains/BlockGrid | SpatialRegion derives from WorldRoot. Each attached region has independent physics and terrain. Workspace remains the default. View selection chooses rendering domain. BlockGrid stores bounded sparse datasets and revisions, with separate authoritative edits, published windows, collision receipts and membership generations. [SpatialRegion](../../../assets/classes/SpatialRegion.luau) · [BlockGrid](../../CurrentArchitecture/BlockGridStorage.md) · [Qualification](../../Validation/SpatialConstructionQualification.md) | A region switch changes spatial membership/view inside a session. Preserve domain identity during pause. Reuse grid/terrain serialization for selected persistent content and repopulate current collision readiness after load. |
| Edit, PreRun, Play | EditorHost captures committed authoring state and creates a separate Play runtime. Stop destroys that runtime, retaining authored history. PreRun compiles bounded ordered schema contributions in disposable VMs within one candidate transaction. Saved but inactive source can block Play/package capture. [PreRun](../../CurrentArchitecture/PreRunAuthoring.md) · [Play](../../CurrentArchitecture/PlaySession.md) | Attach the application run inside existing Play. Leave world within it. Retain the current top-level Stop, debugger ownership, document draft semantics and project mutation authority. |
| Quit and settings | ProcessService::ExitAsync checks ProcessControl and runtime host interprets MarkExit. Graphics, semantic input definitions and session mix controls exist, but this source inspection found no package-level local preference catalog, persistent player-facing display selector or general save picker. [ProcessService](../../../src/services/ProcessService.cpp) · [Input actions](../../CurrentArchitecture/InputActions.md) | Narrow native local Quit intent, backend-validated settings and a local catalog close gaps without delegating process control. |

## Comparative research

These are design inferences from the cited first-party contracts. None establishes Gargantuan behavior.

| Reference | Mechanism | Decision for Gargantuan |
| --- | --- | --- |
| Roblox | ReplicatedFirst prioritizes a client loading interface. TeleportService exposes transition failure and a loading-screen handoff. A replicated early script still depends on a server. [ReplicatedFirst](https://create.roblox.com/docs/reference/engine/classes/ReplicatedFirst) · [TeleportService](https://create.roblox.com/docs/reference/engine/classes/TeleportService) | Keep early dependencies small and make recovery observable. Put title startup before session admission. |
| Godot | SceneTree has a current scene and optional root autoloads. Pausing stops physics, while selected nodes can process; signals can still call scripts. [SceneTree](https://docs.godotengine.org/en/4.4/classes/class_scenetree.html) · [Pausing](https://docs.godotengine.org/en/stable/tutorials/scripting/pausing_games.html) | Keep a persistent presentation owner and explicitly classify synchronous callbacks. Avoid requiring creators to mark every HUD node. |
| Unity | A persistent root can survive scene loads. timeScale controls scaled timing, including FixedUpdate and scaled waits at zero. [Scene lifetime](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Object.DontDestroyOnLoad.html) · [Time.timeScale](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Time-timeScale.html) | Preserve one registered UI owner. Select a clock per execution scope and keep OS deadlines independent. |
| Unreal | The session interface separates creation, discovery, admission, leaving and owner destruction. Resolving a connection and travelling to the world are distinct steps. [Online subsystem session interface](https://dev.epicgames.com/documentation/unreal-engine/online-subsystem-session-interface-in-unreal-engine) | Expose one join operation with progress through discovery resolution, handshake and world readiness. Keep host teardown separate from guest departure. |
| Minecraft | Creating or selecting a persistent world and enabling multiplayer/LAN are separate user actions. Bedrock documents pause behavior conditioned on singleplayer. [World and LAN workflow](https://www.minecraft.net/en-us/article/how-play-minecraft-server) · [Singleplayer pause](https://www.minecraft.net/en-us/article/bedrock-pause-feature-support) | Pass the same SaveId to local start or host. Derive effective pause from authority. An app can choose its own menu policy. |
