# What PauseGameplay suspends

**Proposal.** Pause is a session-authority decision committed between complete simulation turns. The caller receives an operation. Its successful boolean value is the *effective* paused state after applying this owner's request. A refused request returns a typed failure. `IsGameplayPaused()` reads the committed value. Before a world exists it returns false and a pause request returns NoSession. A remote observer reads the last authenticated authority update for the current generation. If disconnected, treat the simulation as absent.

### Clocks and owners

* **Simulation time** advances by admitted simulation delta only. Preserve the simulation ordinal, remaining timer durations, partial fixed-step remainder, interpolation state and subsystem playback positions across a pause. Sample the host clock continuously. Rebase the previous simulation sample on both edges. First resumed frame receives only post-release elapsed time, with the ordinary step/clamp policy. Apply no accumulated pause debt. Exact zero is valid at the edge.
* **Application time** is a local monotonic presentation clock. Drive app tasks, UI tweens, menu animation and progress while the app is being serviced. Suspend or rebase it on OS suspend/debugger park to prevent a frame storm on wake. Handle overdue application timers with a bounded ready queue and stable ordering. A 60-second gameplay pause on a running app advances app time by 60 seconds.
* **Wall time** governs storage deadlines, transport liveness, execution budgets and external leases. Use steady elapsed time locally and trusted provider expiry for credentials. Existing calendar/wall-clock Luau APIs keep their meanings. A game that wants an exact gameplay clock should integrate simulation deltas or use a future read-only simulation-time accessor.
* The native host binds time and scope when entering script code. Capture app/session generation, managed execution identity and authority on signal connection, task submission, operation creation and callback registration. A closure's new parent, a field named “UI”, or a module required in both VMs cannot transfer authority. Default to gameplay for existing world scripts. The entry and selected menu scripts run on app time.
* Keep synchronous edges explicitly gated. `task.spawn` can resume immediately. `Signal:Wait` and normal signal listeners can enter Luau outside the delayed-task heap. An app callback sees value snapshots through the host bridge. Never deliver paused gameplay callbacks through a cross-VM Instance. Suppress transient gameplay edges while parked, coalesce state-style updates to latest, and retain bounded terminal results for outstanding operations. Resume eligible continuations in stable due-time/submission order under a per-frame budget. Under overflow reject new work or close the affected request explicitly. Never silently discard an authoritative user write.

### Pause ownership and authority

Use one idempotent hold per **resumable control owner** per session generation. For ordinary games this is the application-entry execution, including its UI callbacks and modules invoked by it. Independently managed menu Scripts or native system controllers have separate holds. Repeated Pause by one owner takes one hold. Resume releases only that owner's hold. A successful Resume may therefore return true. Source disable, activation retirement, authority revocation and session teardown release the matching hold. Host recovers a retired owner even when the world is parked. Use an internal hold table before considering a public token API.

Admit a simulation hold only from a control execution that can release it while paused. A world-only execution without that route receives NotAuthorized. This avoids stranding a game whose only resume handler lives in the parked world. A dedicated server uses a preauthorized native control owner with an out-of-band resume/timeout path. A future server Luau control binding must be installed explicitly on that live control lane. Ordinary server gameplay Scripts have only their existing gameplay authority.

| Runtime / caller | Pause result | Input and evidence of authority |
| --- | --- | --- |
| Offline app, active world | Commit local hold at next simulation boundary. | Menu can remain interactive. A passive HUD can stay visible with gameplay paused. |
| Private loopback singleplayer | Native private owner requests its one server's pause. Complete only after server ACK for generation and sequence. | Enforce sole local admission by configuration. Peer count alone cannot turn a public server into private singleplayer. |
| Listen-style multiplayer | Ordinary host-player UI receives NotAuthorized for global pause. | Host controller may separately enable an authenticated administrative authority. Opening host UI suppresses that player's input only. |
| Dedicated multiplayer | Only trusted server control with enabled policy can pause all gameplay domains. | Apply ordered epoch/sequence and paused-at-tick, notify clients, acknowledge only after commit. Dedicated host stays headless. |
| Remote client | Local Pause and Resume return NotAuthorized. Client cannot clear server holds. | Show local menu, suppress raw/semantic gameplay input, continue world updates. No server-pause command is emitted. |
| Authenticated server-wide pause | Only available with negotiated support, verified control owner, session generation and authority policy. | Publish paused state on join/resync, deny stale or duplicate transitions, suspend prediction on commit, reset interpolation/intent on resume. Hold unsupported peer combinations out of this optional feature. |

Normal Player and dedicated Server bootstrap remain separate. The local Player connected to a colocated Server still has ordinary network identity. For private pause, pass the host-owner grant via a private native lifetime channel and bind it to the exact child/server session. Never infer administration from LAN location, being the first Player, owner display name or a client-supplied PlayerId.

### Subsystem contract

| Path | While its authority is paused | Resume / qualification witness |
| --- | --- | --- |
| Workspace and SpatialRegion physics | Skip all gameplay physics steps, solver integration, contact generation and time-based advancement. Preserve body IDs, velocities and accumulated sub-step remainder. | No teleport, impulse spike, repeated collisions or extra substeps. Sample two independent regions plus ordinary Workspace. |
| Characters and interaction | Gate PreSimulation locomotion, prediction, root motion, move/transfer commits, input hold duration and prompt timers. Withdraw held input to zero once. | Current authority/control epoch, neutral intent until fresh edge. No deferred jump, attack or completed hold from paused time. |
| Gameplay Scripts and Modules | No new managed script starts, simulation signal turns, gameplay RPC execution or timer resumes. Permit native cleanup and non-script state maintenance. | Park ready continuations within bounds. New script activation validates generation again. Drop stale owner callbacks. |
| Scheduled and delayed tasks | Existing waits/deadlines retain remaining simulation time. Spawn/defer inherit the caller's lane. Waiting on an external result may complete natively. | `task.wait` reports elapsed in its owning lane. Due jobs run once, with a drain budget. Self-deferrals cannot starve UI or transport. |
| Frame callbacks | Omit gameplay PreSimulation, PostSimulation and gameplay PreRender. No synthetic frames with zero delta. | In app scope project only the presentation callback PreRender with app delta. Native renderer still paints. |
| Animation and particles | Preserve gameplay track pose/phase, event cursor and root motion. Freeze emission, age and seeds for future gameplay particle systems. | No burst of markers/particles or retroactive root motion. App-owned viewport animation may advance on app time. General particle-runtime coverage is prospective. |
| Audio | Shared local output continues. Freeze gameplay voice sample cursors and gameplay completion callbacks. App music and UI voices advance. | Fence or drain already mixed bounded audio blocks at a safe buffer edge. Measure maximum audible tail, resumes and completions. Muting alone advances the cursor. |
| Tweens | Hold session-owned TweenService progress and Completed dispatch. Step app-owned tweens normally. | Fresh delta, one completion, cancellation on owner destruction. |
| Rendering and GUI | Republish last stable world plus current app UI at display cadence. Allow resize/device reset and immediate UI layout, text input, focus, hits, menu scripts and UI timers. PlayerGui gameplay scripts remain parked. | Fresh render and input presentation generations. Never deliver a click queued against a retired bitmap. |
| Local controls and camera | Maintain OS focus/text/close events. Gate gameplay raw input, ActionMap/InputService, camera/controller and pointer lock before gameplay listeners or polling state. Capture only opted-in app actions and visible GUI targets. | Release holds/capture, clear key repeats/axes and require physical release/repress. If camera owner changed, restore only the current one. |
| Networking | Service transport poll, liveness, handshake deadlines, disconnect and orderly control. During global pause permit bounded baseline/readiness/replica maintenance. Suppress gameplay Remote delivery and actions. Receiver uses a bounded frozen snapshot or resync for new peers. | Separate service ordinal/deadline from simulation ordinal. Coalesce latest state. Reject/rebase stale input, RPCs and transfer receipts. Ordinary local menu on a running remote session makes none of these server changes. |
| Persistence and content | In-flight I/O, deadlines, cancellation and native result retirement proceed. A known completed reply can wait for a live script. Stage immutable loads off Main. Defer publication that would activate gameplay or trigger callbacks. | Verify owner, revision, package namespace and generation before admission. Never replay unknown-outcome writes. Keep memory bounds active through pause. |
| Spatial construction | Freeze simulation across all attached domains, gameplay grid mutation, movement/collision installation commits with gameplay side effects. Keep package bytes and bounded transfer bookkeeping serviceable. | Recheck grid membership, installed content/collision and bilateral transfer fences at commit. Do not synthesize domain unload/reload. |

A future domain-specific pause would need explicit handling for cross-domain constraints, transfers, script ownership, focus/replication and deadlines when only one side advances. A domain ID expresses spatial membership inside a world. It cannot select a session or save. Global gameplay pause needs no public domain selector.
