# Implementation and qualification gates

**First vertical slice:** one existing offline title exported both ways. Its opt-in Player shows a runtime ScreenGui, starts one offline world, parks simulation while the title remains interactive, returns to title, starts a fresh world and quits. Its ordinary export retains direct startup. Approve the package-entry and lifetime ADR before presenting any of the proposed method names as a supported contract.

## Studio integration

1. **Edit.** Expose the optional ApplicationEntry project reference in ordinary project properties, using the existing Script picker/editor and durable asset/source references. Select a direct child client Script of the designated Folder. Validate ownership, client audience and references at capture and report issues at their authored source/GUI node. Changes to the designation use the existing authoring transaction, save and undo paths. Existing titles default to absent. Keep the in-progress document editor's tabs, drafts, active source revision and reconnect recovery intact.
2. **Preview.** Let a creator preview a chosen ScreenGui with GuiRuntime's existing noninteractive authoring preview in the established viewport. Show safe area, text and authored ViewportFrame camera. The preview does not create LocalPlayer, execute scripts or accept game input. Select the root by authored identity; one preview frame has one displayed-generation receipt. Previewing dependency errors uses bounded inline diagnostics.
3. **Play.** Negotiate an optional EditorHost capability and start option on `StartPlaySession` (e.g. `LaunchMode = "Application"`). Default existing calls to today's Play. Capture the exact committed project revision, active schema and client presentation closure. A saved PreRun edit requiring reload still returns PreRunReloadRequired. Unsaved editor buffers follow the existing document commit policy. Ordered PreRun remains DefineSchema-only. The normal TestSession owns one app run containing zero or one world. Keep world generation distinct from its outer PlaySessionId.
4. **Input and diagnostics.** Route Play viewport input to the app first for reserved app actions/visible controls, then through the qualified Desktop input path for an eligible world. Use the displayed surface/placement generation across focus, resize, renderer restart and deferred pick. Expose read-only app/session/ready/pause state and phase, current authority, bounded reason codes and source locations through existing diagnostics. In Edit, Escape stays an editor input. In Play, explicit Stop is always available, including on a failed launch.
5. **Test scenarios.** Use the same app entry and runtime compiler for test, export and Player. Within one outer Play ID, test pre-world title, offline pause/step timing and two return-to-title loops. Test private host and two independent clients, local overlay while the other client moves, stale connect completion after Stop, refused endpoint, abrupt loss and retry. Use deterministic transport/provider failure fixtures and private disposable profiles. Test debugger parking over an app pause, editor focus loss, IME composition and renderer resize. Add shipped pair tests alongside Play coverage.
6. **Stop and quit.** Leave inside Play returns to the title. Application Quit requests stop of this sandbox, never native Studio process exit. Toolbar Stop retires the entire app plus child, VM, owned transports, profiles and callbacks. Reopen/restart gets new IDs. Cross-check authoring revision, dirty state, undo history, source draft and selected document before/after. Defer Studio patches until the current document, interaction and PreRun owners have a compatible integration pin.

## Performance, limits and failure isolation

Proposed starting limits for measurement are one app entry, one active world, one foreground transition, one local Server child, one registered menu; at most 1,024 presentation instances in an admitted template closure and eight visible 3D viewports per surface, subject to stricter existing runtime bounds. Start with 64 listing/save rows per page, 256 retained listings, 128 bytes per displayed name, 256 bytes per direct address, 64 bytes per seed and 2 KiB per UI error. Bound total descriptor/catalog bytes, paging lifetime, progress/callback queues, preference keys/bytes, pending handles and disk capacity as well as per-item lengths. Reject oversized input atomically. Record and revise these candidate limits against actual projects. Existing subsystem bounds remain authoritative.

Profile no-menu startup, menu time-to-first-present, time to first input, graphical frame P50/P95/P99, longest Main stall while joining, app idle CPU/GPU, extra VM heap, total working set, per-frame queue service and release latency for each graph/device/resource. Record packed bytes by audience, thumbnail/viewport allocations, stored slot bytes and voice-buffer tail. Use same-machine, same-revision paired runs (headless plus normal window), cold/warm starts and two simultaneous clients. Count active worlds, Lua references, pending work/bytes, job handles, listeners, provider locks, texture/voice IDs, input captures and child processes at each return to title. Fail deterministic tests for any stale callback or retained session owner. Require plateau after bounded caches warm. Establish hardware-specific budgets from baselines before deciding release tolerances. The research probe measures logical time and correctness only.

Native security scope is nondelegable. Enforce the same checks on reflected methods, signal continuations and native command dispatch. Keep executable path/arguments, filesystem roots, network policy, publisher trust, credentials and identity choice in trusted hosts. Package validation must cover the app projection and dependency closure before executing code. App time is a scheduling policy, never a trust grant. User-facing errors should be actionable, local and bounded. Quit and input suppression affect only the caller's local Player or Studio sandbox. Group state notifications by generation, redact endpoint secrets and include correlation in native diagnostics. Test denial from PreRun, Edit, remote replica, ordinary client, game script, retired operation and mismatched package. No modal native failure window is needed.

## Remaining decisions

| Decision | Recommended starting point | Evidence required to close |
| --- | --- | --- |
| Private app graph/VM cost vs a future single-VM host | Opt-in private graph and existing Luau VM. An intact DataModel/VM session can retire without migrating userdata, module caches or callbacks. A stable public second DataModel adds no required creator action. | Measured startup/heap and multi-VM diagnostic isolation. Remove ambient `CurrentState` assumptions in diagnostics; verify teardown under nested native callbacks. |
| Save ordering and durability | One authoritative writer, commit blobs before catalog root, pin generator/schema and expose uncertainty. Keep automatic save cadence as game policy. | Crash/recovery on supported filesystems, GC of unreferenced blobs and byte limits, durable operation ledger or equivalent revision reconciliation. |
| Independent direct/LAN authentication | Use only supported profiles; independent trust configuration and discovery are separate from Node. Avoid silent downgrade. | Deployment trust UX, secure listener enrollment, compatibility/version agreement and replay/cancellation qualification. |
| Accessible menu backgrounds and device ownership | Existing 2D GUI and local ViewportFrame first. Future live world backdrops require a separate proposal. | Normal-renderer compositor, focus/accessibility tests and sample-accurate owner-based mixing. |
| App-authorized server-wide pause and remote deadlines | Stage after ordinary offline pause/remote menu. Require resumable admin owner and negotiated client support. | Dedicated + listen tests for unknown peer versions, join while paused, control-channel loss, finite expiry policy and re-election/cleanup. |
| Runtime settings surface | Persist simple local preferences and existing mix/input settings first. Add only validated display controls after restart/rollback testing. | Platform-specific display rollback, device loss, interrupted preference write and profile isolation. |
