# Spatial construction production qualification

## Source and execution

The production baseline is `284443879fcecc66a0257006fcdf7d65566fef4d`. A local Git archive of that commit and the existing Windows worker's baseline source archive had the same SHA-256, `fd99294bb08bf6d8f611c12772bf8d764822727a7a0f5c8a93cb891f7ebb0bed`. Each subsequent commit delta is checked against its predecessor before staging. Runtime class code is regenerated with Lute 1.0.0 when generator inputs change. Unchanged generated bytes retain their previous timestamps so Ninja can use normal dependency tracking.

The November 27 worker configurations use separate private source and build directories for each platform. Windows uses x64 Release MSVC 14.51.36231, CMake 3.31.10, Ninja, genuine shaderc, SDL, Box3D, GameNetworkingSockets and SQLite. Only the pre-existing dependency inputs are shared. Windows build concurrency is six. Linux uses Ubuntu 24.04.4, Clang 19.1.1, GCC 14 headers, CMake 3.31.10 and its installed glslc, running headless in a network-disabled three-CPU container with a 6 GiB memory limit. Its private RelWithDebInfo profile enables ASan and UBSan with nonrecovering diagnostics, uses line-table debug information, and disables GNS and the optional serialization benchmark. These profiles run the named project targets and CTest entries. The Linux profile does not reproduce every hosted CI build option.
