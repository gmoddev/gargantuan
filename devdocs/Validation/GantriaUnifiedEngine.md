## Integrated boundaries

- Workspace remains the terrain authority. Dense palette and fine detail
  remain the defaults. Lossless columns and mixed visual density retain
  their explicit policy or project opt-ins. The default empty field does
  not create a package terrain closure.
- A captured terrain snapshot contains the matching GTMF and GTCH artifacts
  at the authored revision. Local Play receives the same terrain admission
  as project reopen before creating its isolated Engine. Team Create keeps
  its own RPC authorization and journal cursors. The debugger can pause only
  the owned local Play VM.
- Ordinary sessions keep GSES v2. Managed runtime pairing keeps its distinct
  GSES v3 identity. Terrain sessions use GSES v4 with the exact 32-byte
  terrain binding. Trusted loopback Development may defer only its
  manifest-pinned dormant chunks. Managed Offline Player verifies the full
  closure. Managed network targets reject terrain until the audience path
  is qualified. See the [terrain handshake](../../docs/adr/TerrainNetworkBootstrap.md)
  and [managed package contract](../../docs/protocols/Runtime-Distribution-Package-v4.md).
- The native stage preserves the MC33 notice alongside the RC1 component
  notices and MPL source delivery. Game packages exclude app-local Microsoft
  VC++ DLLs and the Microsoft installer. Stage against matching covered-source
  input and review each selected dependency profile. See the
  [release staging procedure](RuntimeReleaseLicensing.md).
- SQLite remains a local development provider. The Server's optional Node
  adapter requires its trusted native endpoint, root certificate, and
  tenant-bound workload credential. The Studio Play launch path exposes its
  existing local modes. Separate Node development admission still requires an
  accepted launcher binding, a disposable tenant, and live qualification.

## Qualification scope

The original Windows and Linux terrain observations, Foundation 12
receipts, and legal inventory remain evidence for their own inputs. A new
private pair must verify the combined EditorHost, GASP v2, local Play and
debugger, trusted terrain multiplayer, Managed Offline export, Relay,
Team Create, runtime inventories, and recipient source recovery. The
affected Engine test targets are GameSessionTests, terrain native and GNS
suites, packaging and EditorHost packaging, the root debug VM and Script
binding, Team Create authority, and the Relay sample.

Windows uses the qualified x64 MSVC 14.51.36231 and SDK 10.0.28000.0 input
profile. Linux terrain qualification used the pinned GNS revision
2cb93a06350bb065db53abdb0d87cf297e0bfd34. Record the actual toolchain,
runtime dependency inventory, repository tree, source archive digest and
binary hashes on each new receipt. Neither baseline receipt authorizes public
delivery or supplies evidence for an untested combined runtime.

The local Windows MSVC codec fixture linked the combined GameSession sources
and passed version 2, 3 and 4 round-trips, wrong-version rejection, empty
terrain binding rejection and combined-identity rejection. The legal
compliance suite passed three checks. Local syntax checks covered changed
Engine, EditorHost and packaging units and the focused regression targets.
The complete native candidate remains subject to the separate Windows and
Linux runs.
