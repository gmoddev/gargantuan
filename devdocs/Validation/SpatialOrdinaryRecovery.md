# Ordinary Workspace performance recovery

## Owner decision

**Hold promotion under the existing 2% rule.** The 24-anchored-Part scene measured a paired +4.13 µs change in whole-step p95 (two-sided 95% interval −2.47 to +10.73 µs). The estimate is below 2%, but its one-sided upper bound and the prespecified missing-tick upper bound both exceed the ceiling. The six-moving-body sensitivity scene qualified under both checks. The accepted Linux sanitizer privacy correction carries forward. [Final qualification and reproduction](SpatialOrdinaryOptimized.md)

The final comparison accounts for all 311,300 native ticks in 320 scheduled processes. It preserves both original scene definitions, CPU placement, randomized order, warmup, p95 estimator and acceptance rule. One additional launch failed during project creation before warmup. Recovery preserved all 148 completed records and their tick data, then resumed at block 38, run 1. Independent replays reproduced the paired estimates. The original anchored comparison measured +4.41% (+21.22 µs), upper +6.52%. The historical executable’s median per-process p95 changed from 479.15 µs in that campaign to 389.85 µs in this one. The difference between campaign estimates therefore does not isolate the treatment effect. ## Where the stock products spent the time

Eight balanced four-process blocks measured the original native phases within the same slow ticks in both stock executables. The mean increase for ticks in the 94th–96th percentile band was 30.31 µs. Physics contributed 7.64 µs (two-sided 95% interval +4.41 to +10.86). PreSimulation contributed 19.82 µs (−2.05 to +41.68). In the slowest 5%, the PreSimulation contribution was 24.01 µs (+5.87 to +42.14). The engine runs the default player movement script in that phase even when every authored Part is anchored. [Phase and package controls](SpatialOrdinaryAttribution.md)

The default scripts look up class names through reflection. In a matched Play probe, each round timed 256 pairs of a positive character check and a negative Part check, using short or fully qualified names in alternating order. Four fresh processes ran historical, current, current, historical. Median within-round short-name overhead per call was 105.75 ns historically and 103.65 ns currently. Short-name lookup did not explain the PreSimulation increase. [Lookup data](SpatialOrdinaryAttribution/Locomotion/Lookup.csv) · [Probe](../../tests/SpatialOrdinaryScriptCalls.py)

An ordinary character with an anchored, noncollidable root was placed at the same clear position under zero, four, or twelve folders. Each of four fresh stock Play processes compared 48 zero-motion calls to `Character:Move` against 48 direct `Workspace:MoveKinematicCapsule` calls, alternating their order. The two paths reached the same position with zero translation and no floor. Across historical processes and depths, the median paired extra cost of character admission ranged from 0.16 to 0.36 µs. In the spatial product that cost grew from 0.70 µs at depth zero to 1.33–1.53 µs at depth four and 2.33–2.36 µs at depth twelve. The extra ancestry traversal is visible independently of rendering or native collision complexity. Hot batched calls measure a different workload from the full-step p95. [Motion path receipts](SpatialOrdinaryAttribution/Locomotion/MotionPaths.csv) · [Probe](../../tests/SpatialOrdinaryScriptCalls.py)

The same motion probe then compared the released spatial product with an uninstrumented eight-translation-unit relink of `4af419f00` in current, corrected, corrected, current order. At depth zero the released process medians were 0.77–0.96 µs and the corrected medians were 0.50–0.63 µs. At depth twelve they were 2.35–2.63 µs and 1.61–1.64 µs, respectively. ## Implementation and correctness review

The instrumented stock-versus-historical comparison located 9.75 µs of extra time in `Character::AdmitMotion` outside its nested `WorldRoot::ResolveKinematicMotion` call on the 94th–96th whole-step ranks (95% interval +7.43 to +12.08 µs). That nested call includes domain and terrain checks, pending physics updates and the capsule solve. Render publication on the same ranks cost 11.00 µs more (+4.69 to +17.30), and the main thread used 118,500 additional scheduled cycles (+27,700 to +209,300). The additional timer on effective-world resolution runs only in the binaries that perform that operation. The uninstrumented hierarchy-depth comparison separately confirms the ancestry cost. Windows exposed scheduled cycles and switches but had no configured hardware cache counters. [Counter scope, calibration and stock comparison](SpatialOrdinaryNativeCounters.md)

The direct operation probe compared the stock spatial Engine with the correction across 640 ordinary ticks per arm. Both issued 620 incremental render publications. The corrections eliminated the following measured work:

| Extra assignment-walk node visits / parent weak locks | 1,920 / 1,280 | 0 / 0 |
| Empty prompt cell probes | 118,098 | 0 |
| Shared schema ownership copies for synchronous reads | 38,840 | 0 |
| Eager reflected class names on writes | 2,720 | 0 |
| Collision asset service lookups / journal reads | 1,280 / 1,280 | 0 / 0 |
| Anchored Part visits in ordered dynamic readback | 8,950 | 0 |
| Idle terrain polls | 640 | 0 |
| Allocations / requested bytes in empty grid setup | 2,480 / 634,880 | 0 / 0 |

The structural counts show which memory accesses, shared ownership operations and journal locks disappeared. The mesh observer itself still ran 1,280 times in both arms. Small scenes already use direct execution. The construction campaign did not install a global adaptive strategy switch in this path. In a separate six-block stock-versus-corrected timing run, the corrected product saved 4.59 C++ allocation calls and 540 requested bytes per tick on average. Physics saved 1.89 µs per tick (95% interval 0.61 to 3.16) and 7.00 µs on the 94th–96th whole-step ranks (1.51 to 12.49). Whole-step p95 changed by −2.38 µs (−38.89 to +34.14). The corrected versus stock admission time outside the nested world query changed by +0.02 µs on average (−0.85 to +0.89), leaving the full stock-to-historical admission difference unexplained by the removed ancestry work. Isolating mesh observation in its own matched build reduced mean PreSimulation time by 17.12 µs (11.22 to 23.03). The experiments used different binaries and process cohorts, so their phase savings cannot be added. ### Implementation history

The production history separates costs introduced by spatial construction from existing ordinary work. Commit `71993ba89` introduced the character assignment walk and empty incremental grid map. Commit `0468dba97` added required motion proof, `800635ccd` added the impulse reservation check, and `92d9f4327` made prompt selection resolve the player’s domain. The historical `284443879` already copied schema owners, resolved class names on writes, probed empty prompt cells, read the mesh asset journal, scanned ordered readback and polled terrain. Removing those older costs improves the ordinary workload too. Their savings do not establish which change caused the original historical-to-spatial regression. ### Remaining domain resolution

Independent review found that a membership cache keyed only by DataModel revision can return a stale world during a reparent callback. The parent pointer already refers to the new parent while the revision and subsystem membership can still describe the old one. A transfer can also stage destination bodies before source retirement. An explicit region binding can remain present after the destination becomes unavailable. Each case needs the underlying authority and lifetime checks. [Parent mutation and notification order](../../src/classes/Instance.cpp) · [Domain resolution and membership](../../src/runtime/SpatialDomainMember.cpp)

One possible future experiment uses live parent identity. If an unassigned RootPart is a direct child of the ordinary Character, and that Character is a direct child of the caller world, those two live links could establish the chart for the supported classes. The world must remain pinned through the query and callbacks. Other hierarchies still need general resolution. The corrected instrumented scene executed exactly one effective-world query per tick, visiting three objects and acquiring two parent references. The entire resolver cost 2.56 µs on average and 4.76 µs on the 94th–96th whole-step ranks, about 0.88% of those steps. These figures include observer work and both required parent checks. They bound the measured component on those ticks, without forecasting a whole-step p95 gain.
